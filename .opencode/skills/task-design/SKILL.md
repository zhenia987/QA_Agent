## Description
Формирование задач для команды разработки на основе проанализированных требований. Создание задач в **Jira** с привязкой к требованиям.

## Inputs
- результат этапа **requirements-review** (проанализированные требования, бизнес-правила, ограничения, критерии приемки);
- указание на проект в **Jira**, в котором должны быть созданы задачи;
- правила и место хранения **Artifacts** (структура, формат, идентификаторы этапов).

## Workflow

### 1. Подготовка задач
- На основе каждого функционального требования сформировать отдельную задачу.
- Если несколько требований логически связаны — объединить в одну задачу, явно указав связь.
- Для каждого бизнес-правила, ограничения и критерия приемки определить, требуется ли отдельная задача или дополнение к существующей.

### 2. Оформление задачи
- **Название**: краткое, понятное, отражающее суть функциональности.
- **Описание**: содержит функциональное требование, бизнес-правила, ограничения, критерии приемки, ссылку на источник (Confluence).
- **Связь**: указать ID связанных требований.

### 3. Создание задач в Jira
- Создать задачи в указанном проекте Jira.
- Проверить, что дубликаты не созданы.
- Зафиксировать присвоенные ID задач.

### 4. Сохранение результата
- Сохранить результат этапа в **Artifacts** с идентификатором этапа.
- Включить: список задач с ID, названиями, описаниями и связями с требованиями.

### 5. Проверка качества (Quality Gate)
- каждая задача соответствует требованиям;
- каждая задача имеет понятное название и описание функциональности;
- не созданы дубликаты задач;
- присвоены ID.

## Outputs
- набор задач в **Jira** с ID, названиями и описаниями;
- связь «требование → задача»;
- артефакт этапа, сохранённый в **Artifacts** со статусом прохождения **Quality Gate**.

## Constraints
- не создавать задачи в Jira, которые не имеют основания в требованиях;
- не придумывать отсутствующие бизнес-правила, ограничения и критерии приемки;
- не удалять существующие в Jira задачи.

## Failure Behaviour
- если **Jira** недоступна или создание задачи завершилось с ошибкой — остановиться, сообщить пользователю;
- если **Artifacts** недоступны — остановиться и сообщить пользователю;
- если **Quality Gate** не пройден — зафиксировать в артефакте и не помечать этап успешным.
